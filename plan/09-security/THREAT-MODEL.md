# Threat model

| Status | Owner | Updated | Feeds |
|--------|-------|---------|-------|
| reviewed | ai | 2026-10-13 | every `risk:*` issue |

Dear Steven is a single-operator app with no accounts. The assets worth protecting are the
operator's **OpenAI budget**, the **integrity of attribution** (the product must not put words in
anyone's mouth), the **operator's keys**, and the **user's voice and questions**.

## Entry points and requirements

| Id | Entry point | Threat | Requirement | Proven by |
|----|-------------|--------|-------------|-----------|
| SR-01 | `POST /api/ask` | Oversized / malformed bodies, prompt stuffing | zod strict schema; ≤ 64 KB body; ≤ 2,000-char question; ≤ 11 history turns; `mode` only `ask` or `talk` (P7-05), and talk changes nothing but a fixed style note; `about` (P7-08) ≤ 600 chars, angle brackets neutralised so it can't close or open a tag, with a fixed rule that it is relevance only, never evidence | `AskRequestSchema` (core), route |
| SR-02 | `POST /api/ask`, `/api/transcribe`, `/api/speech` | Budget drain by scripted requests, many clients or many IPs | Per-client token buckets on every paid route (live mode); demo is free and unlimited. The client is the address this deployment can trust (P8-01): the last `X-Forwarded-For` entry by default, the last of `DEAR_STEVEN_TRUSTED_PROXIES` entries, or only `DEAR_STEVEN_CLIENT_IP_HEADER` when the platform sets one; never the first, client-written entry; IPv6 by /64. The limiter drops only entries that have refilled anyway, never the shared (`EVERYONE`) buckets, and while every tracked client is still limited a new one waits too, so a flood of made-up clients resets nothing. Daily cap `DEAR_STEVEN_DAILY_BUDGET_USD` (P6-08): every paid call records its estimated cost (core `PRICES`, from token usage) in `data/spend.json`; at the cap, paid routes make no OpenAI call until midnight UTC (ask: in-persona resting reply; speech/transcribe: 503, browser fallbacks); unreadable budget = 0, unreadable ledger = spent (fail closed); in-flight requests may overshoot by a fraction of a cent each. Optional access gate `DEAR_STEVEN_ACCESS_CODE`: the proxy refuses every `/api/*` route but `/api/access` without a signed cookie (`<expiry>.<HMAC-SHA256>`, keyed by a hash of the code; `HttpOnly`, `Secure`, `SameSite=Strict`, 30 days); code compared by hash; 5 guesses/min per client and 30/min in all | `server/rate-limit.ts`; `rate-limit.test.ts` (a 20,000-client flood refills no one); `client-address.test.ts`; `spend.test.ts`; `access.test.ts`; `proxy.test.ts` (every route on disk → 401); `app/api/ask/route.test.ts` (past the cap: resting reply, no network call); `e2e/access.spec.ts` |
| SR-03 | Transcript text in the prompt (answers; whole transcripts for summaries, P8-03) | Prompt injection via a passage ("ignore previous instructions…") | Sources wrapped and marked untrusted; `<`/`>` neutralised so text can't close tags; summaries are checked in code before they are stored (every quote located in its passage, numbers, names and attribution in the machine-written text, `summary/summary.ts`), and the store validates them against `ConversationSummarySchema` on the way in and out; validator independent of model obedience | `answer/context.ts`; validator tests; `summary/summary.test.ts` (quotes located or dropped, numbers, names, attribution); `summary/prompt.test.ts`; `store.test.ts` (summaries validated in and out) |
| SR-04 | Model output | Fabricated citations, quotes, guests, conversations, host claims | Nothing streamed before `validateBlock`; ids must be retrieved; quotes re-derived from storage; downgrade after one repair | `validate.test.ts`, `compose.test.ts`, `quotes.test.ts` |
| SR-05 | Server logs / error events | Leaking keys or provider messages (which can echo masked keys) | `describeFailure` maps errors to fixed messages; logs only status codes | `server/errors.test.ts` |
| SR-06 | Client bundle | Keys or server modules shipped to the browser | `readConfig` server-only; dependency-cruiser forbids client → server core; `server-only` guards | `pnpm arch` |
| SR-07 | `/api/passages/:id`, `/api/passages/:id/related`, `/api/episodes` | Path/SQL injection; bulk transcript extraction | id regex `^[A-Za-z0-9_-]{1,80}$`; zod-validated query (`q` ≤ 100 chars, `LIKE` wildcards escaped); prepared statements; one passage + a few lines, ≤ 3 related passages, or episode metadata only (30 per page); one shared rate-limit bucket | route (`e2e/api.spec.ts`); store tests |
| SR-08 | FTS5 query from user text | FTS syntax injection / errors | `toFtsQuery` quotes every term, drops operators | `store.test.ts` (`neutralises FTS5 syntax`) |
| SR-09 | `/api/transcribe` | Large or non-audio uploads | ≤ 8 MB; audio MIME allow-list; never stored | route |
| SR-10 | Microphone | Listening without consent | Mic opened only on press/toggle; released on stop; Permissions-Policy `microphone=(self)` | e2e (voice), `next.config.ts` |
| SR-11 | TTS | Audio playing unbidden; a voice that imitates a real person | Speech only after a spoken question, a Listen click, or — with "always speak" opted in — a typed or clicked question in a visit that already has user activation; the speech route accepts only `STOCK_VOICES`, never a custom or cloned voice id | e2e (`typed questions are never read aloud`, voice settings); `schema/ask.test.ts` |
| SR-12 | YouTube links | Link injection via a malformed video id | 11-char id allow-list; otherwise no link | `links.test.ts` |
| SR-13 | Ingest CLI | Unbounded spend | Paid stages need `--budget`; stop before exceeding; dry-run for embeddings. `latest` (P6-16) runs only the free stages without `--budget`, embeds only when the exact estimate fits under it, and never diarizes, so it is safe to schedule | `transcribe.ts`, `index.ts`; `latest.test.ts` (over budget: nothing embedded, OpenAI never asked; no budget: nothing paid; a second run fetches only the feed) |
| SR-14 | Repository and supply chain | Committed secrets or podcast data; a vulnerable or hijacked dependency or action | `.gitignore` (`.env*`, `data/`); gitleaks on every PR and weekly over the full history; `pnpm audit --prod --audit-level=high` on every PR and weekly; Dependabot updates and security alerts; actions pinned by SHA; least-privilege `permissions:` per job; CodeQL once the repository is public | CI `gitleaks`, `check`; `security.yml` |
| SR-15 | Response headers | Injected scripts (XSS), clickjacking, MIME sniffing, injected frames or plugins, downgrade to HTTP | `X-Frame-Options: DENY`, `nosniff`, strict referrer (`next.config.ts`). Per-request CSP from `src/proxy.ts`: `script-src 'self' 'nonce-…' 'strict-dynamic'` (a fresh 128-bit nonce per page, every page rendered per request; `'unsafe-eval'` only under `next dev`), `default-src`/`connect-src`/`font-src 'self'`, `img-src 'self' data: blob:`, `frame-src` youtube-nocookie only, `media-src 'self' https:`, `object-src 'none'`, `base-uri`/`form-action 'self'`, `frame-ancestors 'none'`; over HTTPS also `upgrade-insecure-requests` and `Strict-Transport-Security: max-age=31536000`. zod runs jitless so no eval probe is needed. Accepted: `style-src 'unsafe-inline'` (SSR style attributes; styles can't run code) | `csp.test.ts`; `e2e/api.spec.ts` (headers, nonce on every script, injected markup refused); every e2e test fails on any CSP violation (`e2e/fixtures.ts`) |
| SR-18 | Answers (persona) | A person in crisis gets persona theatre or a fixture; harmful instructions; invented words, endorsements or accusations in Steven's or a guest's name; prompt injection in a question or a transcript | `packages/core/src/safety`: phrase rules at once, OpenAI moderation (free) alongside retrieval; crisis → fixed human-written reply leading with a helpline for the visitor's country (Accept-Language) and the emergency number, no model, no sources, also in demo mode; severe harm → refusal; impersonation → refusal; suicide/self-harm as a topic → helpline leads the answer; medical/legal/financial → `<care>` note (concrete view + when to see a professional); persona-v1.1 rules on real people and on instructions in questions; human review of the copy and helplines (H-11) | `route.test.ts`; `compose.test.ts` (crisis: model never asked; moderation verdict after retrieval; no moderation still answers; preface; care note); `eval/redteam.json` in `pnpm eval` (offline routing, false refusals ≤ 5%; live content checks with `--answers`, and with `--mode talk` for talk mode: 22/22 on 2026-10-13); `e2e/safety.spec.ts`; talk mode: `compose.test.ts` (crisis in talk mode: model never asked; evidence rules unchanged) |
| SR-17 | Conversation memory (IndexedDB) | Personal questions kept on a shared device without consent; a tampered store injecting links or markup | Off by default and nothing written while off (not even an empty database); written only after an explicit switch; Forget / switch-off deletes the database at once; where it is kept is said next to the switch and in "How this works"; on restore, answers are re-validated (`FinalAnswerSchema`) and links rebuilt from ids (`linksAt`). "About you" (P7-08) follows the same rules in its own database (`dear-steven-about-you`): nothing is written until the visitor presses Keep after an interview; what is sent is exactly the text shown; Forget deletes the database at once (undo holds the text in memory for a few seconds); on load it is re-validated (shape, ≤ 600 chars) | `e2e/memory.spec.ts`; `memory.test.ts`; `links.test.ts`; `aboutYou.test.ts`; `e2e/about-you.spec.ts` (keep, see, sent exactly as shown, forget) |
| SR-19 | A visitor's own OpenAI key (P6-03): `x-openai-key` on this site's API requests, `POST /api/key` | The key leaking (logs, responses, provider error echoes, URLs, caches, the spend ledger, other visitors' requests); sent in clear; the server used as an oracle to test stolen keys; a visitor spending the operator's key against their wishes; the operator's cap stopping, or being drained by, a visitor paying for themselves | Header only (never a URL, body or cookie); validated against `VisitorKeySchema` (`sk-` + 20–300 of `[A-Za-z0-9_-]`) before use; refused over plain HTTP except from this machine, and the browser sends it only in a secure context; a fresh client per request, never the cached operator client; errors through `describeFailure` (provider text and masked keys never pass); not recorded in or stopped by the daily ledger; key checks are one free `models.retrieve` with no retries, 5/min per client and 30/min in all, never on the operator's key; `DEAR_STEVEN_ALLOW_OPERATOR_KEY=0` keeps the operator's key from visitors; forced demo ignores it. In the browser: `sessionStorage` by default, `localStorage` (30 days) only on request, stored only after a successful check, Forget removes both and the sealing key; never as plain text (P8-01): sealed with AES-GCM under a non-extractable key in IndexedDB, with where it is kept and when it expires authenticated alongside, and a plain-text value from before is sealed on first read. Sealing protects against reading the browser's files, not against a script in the page, which could use the sealing key: the strict CSP (SR-15) is what keeps injected scripts out. The operator's key (P8-01): no `NEXT_PUBLIC_*` or `next.config` `env`; no route, page or payload carries it | `src/server/visitor-key.test.ts` (canary key through `/api/key`, `/status`, `/ask`, `/speech`: not in any response or log line, not even OpenAI's masked echo; the request runs on it; nothing cached or ledgered; malformed / plain-HTTP / no-key / forced / rate-limited cases); `config/env.test.ts` (`forVisitor`); `schema/ask.test.ts` (`VisitorKeySchema`); `spend.test.ts`; `e2e/own-key.spec.ts` (paste → test → ask → forget; which requests carry it; storage holds no `sk-`, the sealing key can't be exported, a lengthened expiry or plain-text value is dropped or sealed); `lib/visitor-key.test.ts` (sealing: expiry, binding, tampering); `server/operator-key.test.ts` (an operator canary through every route on disk, against an OpenAI that echoes it masked: no 8 characters of it in any body, header or log line; mutation-checked); `e2e/operator-key.spec.ts` (a production server on a canary key: pages, server-component payloads, every script and stylesheet, every API route, DOM, storage, cookies and the server log; mutation-checked) |
| SR-20 | Share links (P6-17): `#share=` fragment, `POST /api/share` | A forged or edited link putting words, quotes, links or markup on screen under the brand — words Steven never said, a quote no transcript holds, a link to anywhere; an old link still quoting an episode taken down since; the disclosure stripped from a share; the question leaking into server logs; a crafted token as a decompression bomb or an oracle | The server signs each answer it writes (HMAC-SHA256 under a per-deployment secret, `data/share-secret`, mode 0600) and opens only tokens whose signature holds (`timingSafeEqual`), so a share can't say anything this copy didn't write; then, as for restored conversations (SR-17), `SharedAnswerSchema` re-validation and links rebuilt from ids — links are never carried in the token. Unless the answer is a labelled demo fixture, every cited passage must still be in the knowledge base with each quote a span of it (`stillSourced` in core), so a takedown reaches links made before it. The token rides in the URL fragment (never sent with a page request) and is cleared from the address bar once read; `ShareTokenSchema` bounds it at 24,000 chars, the request body at 32 KB and the inflated JSON at 512 KB; 20/min per client; nothing stored. The disclosure is part of the page a shared answer opens in and is drawn into every image card; demo answers stay labelled demo | `src/server/share.test.ts` (round trip; one changed character, a truncated or other-version token, another deployment's secret all open nothing; a validly signed non-answer and a 1 MB bomb refused; secret saved owner-only and reused after a restart; a live answer stops opening once a cited passage is gone, demo answers and broken links never touch the store; route end to end from `/api/ask`; rate limit; signature, bomb and takedown checks mutation-tested); `answer/shared.test.ts`; `schema/ask.test.ts`; `lib/share.test.ts`; `e2e/share.spec.ts` (copied link opens the same answer and sources on a fresh page, tampered link opens nothing, image card downloads; axe) |
| SR-22 | Interview mode (P7-06): `POST /api/interview` | Personal answers kept or logged; prompt injection through an answer turning the interviewer; a crisis answer met with another question; invented "facts" about the visitor; budget drain | Strict schema (≤ 10 turns, ≤ 2,000-char answers, ≤ 48 KB body); nothing stored, nothing logged but failure names (`describeFailure`); the safety rails see every answer and the setup line first (crisis / refuse → the fixed reply, no model call); guest text is wrapped and named untrusted in the instructions, and every question is checked in code (one question, ≤ 40 words, persona lint, not a copied style example); "What I learned" and the practice debrief (P7-07) keep only points whose evidence is a span of the visitor's own answers (`locateQuote`), and the page shows that span; a debrief rewrite is dropped if it brings a number they never gave or if under 80% of its content words are theirs; scores are clamped to 1–5; live steps take an `interview` token and count against the daily cap; demo mode is free and fixed | `interview/interview.test.ts` (crisis: model never asked; moderation; evidence check; retry then fallback; copied example rejected); `interview/prompt.test.ts`; `app/api/interview/route.test.ts` (demo end to end; crisis; bad body; past the cap: no network call); `e2e/interview.spec.ts` |
| SR-21 | Guided local setup (P6-04): `pnpm dev:setup`, `GET /api/setup`, `POST /api/setup/keys`, `POST /api/setup/run` | Another site or another machine writing the operator's keys, reading which are set, or spending their OpenAI budget: cross-site requests from any page the operator visits, DNS rebinding, a request through a proxy, a deployment with the variables copied over; a value smuggling extra lines into `.env`; keys echoed back or logged; an embedding run costing more than shown; two stages racing on the database | Off unless the server was started for it: a token of 32+ chars in `DEAR_STEVEN_SETUP_TOKEN` (fresh `randomBytes(32)` per run, printed once in the terminal, carried in the link's fragment and kept for the tab in `sessionStorage`), `DEAR_STEVEN_SETUP_HOST` loopback, `next dev` bound to 127.0.0.1, the ingest CLI on disk. Every request must then name a loopback Host (defeats rebinding), send no foreign Origin and no cross-site Fetch Metadata, pass only loopback forwarding hops and carry the token in `x-setup-token` (`timingSafeEqual`); anything else is a 404, the same as a server without setup. Keys are checked against strict patterns (`SetupKeysSchema`, 4 KB body), written atomically owner-only (temp file + rename, 0600), never returned (the state says only whether each is set) and never logged (write failures log the error name). Stages run as the CLI itself, one at a time; embedding needs a key and a cap (≤ $20) the estimate fits under, checked by the route and again by `index --budget` before any call; paid diarization is not offered. "Bring in new episodes" runs the CLI's `latest` with a $0.05 cap only when an OpenAI key is saved, and the CLI checks the estimate against it before any call. Closing the page stops the stage | `src/server/setup.test.ts` (token, Host, Origin, Fetch Metadata and forwarding checks each mutation-tested; a newline in a value refused before the file is touched; a canary key never in a response; over-budget refused with no process started; one stage at a time; terminal output; abort); `config/env-file.test.ts`; `schema/setup.test.ts`; `ingest/commands/index.test.ts`; `e2e/setup.spec.ts` (404 without or with a wrong token, from another site and on a server not started for setup; keys → transcripts → capped embeddings against a fixture feed and fake OpenAI; the CLI's status agrees; axe) |
| SR-16 | In-drawer player and podcast audio | The user's IP and referrer reach Google and the audio host (and any tracking redirect in the enclosure URL) without consent; mixed or odd-scheme media | Nothing requested before a click; privacy-enhanced youtube-nocookie embed; enclosures used only when https; disclosed in "How this works" | `e2e/media.spec.ts` (request log); `links.test.ts`; `citations.test.ts` |

## Out of scope

Multi-tenant isolation (there are no tenants), authentication (none — see `docs/DEPLOY.md` on
private deployment), DoS beyond per-client rate limits.
